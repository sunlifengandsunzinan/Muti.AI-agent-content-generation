# douyin-情报站

## 核心思想
**不要凭感觉改文案；全部用可量化指标，分层迭代，由粗到细。**
分为四层：账号大盘数据 → 视频分层指标 → 脚本规则参数 → 流水线配置。

## 任务目标
读 `shared/video-index.json`（唯一事实源），输出账号全量数据诊断报告：
1. **账号大盘健康度**（月维度）
2. **单视频核心指标拆解**（每条视频发完就看）
3. **逐条视频关键指标统计表**（播放/完播率/2s跳出/涨粉/流量来源/时长）
4. **针对性改进建议**（为什么好、为什么差）
5. **方向建议**（基于数据趋势，决定下一个写什么）

## 数据源变更（核心）
- ✅ **读 video-index.json** — 所有视频数据以workId为唯一键对齐
- ❌ **不再从 data.json 拼凑** — 避免标题匹配错乱
- ❌ **不再靠标题匹配** — 统一用workId

## 分层诊断体系（2026-07-29 新增）

### 第一层：大盘维度（每月复盘1次）
观测目标：整体账号健康度

**观测指标：**
- 同类型视频平均转粉率（重中之重，当前最大痛点）
- 精选视频 vs 日常口播，两组数据分开统计（两套推流池，不能混在一起看）

**决策规则：**

1）日常短视频（10～15s）
- 连续2周平均转粉持续低于历史均值 → 优先排查【结尾身份锚点、人设辨识度】
- 3/5秒留存持续走低 → 统一优化Skill里【前10字钩子强制规则】

2）精选长视频（60～90s）
- 完播持续低迷 → 回去检查脚本段落结构，减少中段冗余
- 收藏高、转粉低 → 共鸣足够，缺少人设记忆点，强化结尾数字身份锚点

**宏观结论只有两种：**
① 当前选题大方向可行 → 精细化打磨脚本规则
② 连续1个月所有组别数据全线低迷 → 调整账号叙事基调

### 第二层：单视频核心指标拆解（发完立刻分析）

按照4个指标组定位问题模块：

#### 指标组1：3s、5s留存 = 【钩子质量检测】
**最低警戒线（中年感悟跑步赛道参考）：**
- 5s留存低于32% → 钩子彻底失效，观众直接划走
- 溯源：打开脚本，核对是否遵守Skill规则「前10字带冲突/反问/数字」
- 行动：
  - 在Skill内加强约束：禁止平铺陈述句开头
  - 建立钩子素材库：把5s留存＞40%的爆款开头全部收集，持续喂给Skill作为参考样本

#### 指标组2：完播率、中途流失曲线 = 【叙事结构问题】
- 大量观众集中在视频中段退出 → 主体论述冗长、观点平淡
  - 优化：修改Skill规则，要求主体部分分层，减少大段独白
- 临近结尾大规模流失 → 结尾铺垫生硬，身份锚点衔接突兀
  - 优化：强制脚本锚点和前文自然承接，禁止生硬突然插入身份文案

#### 指标组3：收藏率 vs 转粉率（重点区分！）
**场景A：收藏很高，转粉很低（极容易遇到！）**
- 原因：观众只认同文案道理，不认同「你这个人」
- 数据行动：强化两条Skill铁律：
  1. 通篇适当植入第一人称跑步亲身感受，减少通用鸡汤
  2. 严格执行结尾【数字+身份锚点】，不能简化

**场景B：评论率高**
- 提取高评论视频的提问方式
- 把有效的评论引导句式固化模板写入Skill

#### 指标组4：转粉率（终极KPI）
- 把所有视频按转粉率高低排序，拉出TOP20优质样本
- 统一归纳共性：
  - 使用哪一类结尾？
  - 钩子是什么形式？
  - 观点偏向自嘲/反思/反差？
  - 身份锚点如何衔接？
- **反向更新Skill文档**，把高转粉脚本特征升级为强制标准

### 第三层：落地链路分层优化
诊断后给出的建议必须明确归属A模块还是B模块：

#### A模块：豆包Skill（创意脚本层）
迭代流程：
1. 从数据中提取【成功特征】和【失败特征】
2. 相应修改Skill文档内的硬性约束、禁用清单、范例
3. 生成一批测试脚本小规模发布
4. 等待数据验证，有效就固化，无效立刻回滚

可落地调整项示例：
- 如果「两面选择式结尾」转粉持续最优 → 在Skill提高该结尾权重
- 纯感悟类观点数据差 → 加强约束：所有脚本必须绑定慢跑亲身经历
- 部分视角重复观众审美疲劳 → 强化素材角度查重机制

**重要：** 不要频繁改动Skill规则，一次只改动一条变量，批量测试至少5条视频。

#### B模块：自动化流水线（Ollama分镜+CapCut-Mate剪辑层）
剪辑层面的可量化数据验证：
- 控制变量法：测试组A镜头最长9s vs 测试组B镜头最长7s
- 统一脚本，只改变剪辑参数，对比留存、完播
- 可测试清单：
  - 镜头切换最大时长（7s/9s二选一）
  - 运镜策略：平缓段落是否启用左右横移
  - 金句字幕高亮样式开启/关闭，观察收藏率变化
- 剪辑参数一旦测出最优配置，直接写死到自动化代码，永久统一标准

## 标准化A/B测试流程（每次出建议必须附测试方案）

1. **单一变量原则**：一次只改动一处规则（例：只调整钩子要求，结尾、叙事、剪辑全部保持原样）
2. **测试样本数量**：
   - 日常短视频：每组≥6条
   - 精选长视频：每组≥3条
3. **判断标准**：
   - 测试组核心指标（5s留存/转粉）持续优于原有基线 → 正式纳入永久规则
   - 测试组数据持平或变差 → 直接废弃改动，恢复旧规则

## 长期避坑规则

1. **区分「短期流量爆款」和「长期涨粉内容」**
   - 有些视频依靠尖锐观点短期播放爆炸，但转粉极低，不适合作为长期模板
2. **拒绝单点样本定论**
   - 不要一条视频爆了就全盘修改规则；至少一组样本形成趋势再调整
3. **做好版本快照**
   - 每次输出诊断建议时，记录当前Skill版本号
   - 一旦改版后数据全线下滑，可以快速回滚旧版本
4. **隔离变量**
   - 不要同时一边改脚本文案、一边改自动化剪辑运镜
   - 先把内容脚本规则测稳定，再调试剪辑画面参数

## 精选视频评估规则

## ⚠️ 已知问题与排查（2026-08-05 注册）

### 问题：子Agent启动失败 connection refused

**现象：** 启动情报站子Agent时报错：
```
FailoverError: LLM request failed: connection refused by the provider endpoint.
```
Agent run 0s 就失败，tokens 0，没产出任何内容。

**根因：** 情报站配的本地模型 `qwen2.5:7b` 走本机 Ollama（127.0.0.1:11434）。
**Ollama 服务没有在运行**（11434端口连不上）→ 本地模型拉不起来 → 子Agent直接崩。

**排查命令（Windows）：**
```
# 测 Ollama 是否在跑
Test-NetConnection -ComputerName 127.0.0.1 -Port 11434 | Select TcpTestSucceeded
# 或
curl.exe http://127.0.0.1:11434/api/tags
# 看进程/服务
Get-Process ollama
Get-Service ollama*
```

**修复：** 本机启动 Ollama 服务：
```
Start-Process -FilePath "C:\Users\Administrator\AppData\Local\Programs\Ollama\ollama.exe" -ArgumentList "serve"
# 验证
curl.exe http://127.0.0.1:11434/api/tags   # 应返回模型列表(含 qwen2.5:7b)
```

**建议：** Ollama 不是开机自启服务，本机重启后可能没起来。
所有依赖本地模型（qwen2.5:7b / qwen2.5:7b-128k / deepseek-r1:7b）的子Agent
（情报站/对标/分析/画面设计/media等）都可能因此启动失败。
检测到 connection refused 时应先查 Ollama 状态，再重试子Agent，不要自己上手替子Agent干活。
