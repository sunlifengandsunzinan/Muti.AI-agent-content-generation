# Muti.AI-agent-content-generation — 多Agent协作抖音内容生产系统

> **不是全自动流水线，而是人机协同 — 人做决策，Agent执行，数据和创意形成闭环。**

## 设计背景

运营一个抖音账号（"40了，得干点儿啥了"）时面对几个实际问题：

1. **素材管理混乱** — 口述故事散落在对话中，每次写脚本要重新回忆
2. **标题凭感觉** — 没有系统参照赛道趋势，标题质量不稳定
3. **缺少数据反馈** — 数据靠手动查看，看不出趋势
4. **创意重复** — 不知道哪些素材用过了、哪些角度还没开发

为了解决这些问题，设计了这套多Agent系统。Agent之间通过标准化的数据文件协作，总助（Manager）负责调度和验收。

## 双机分工（封号红线的设计）

两套操作必须分机器，原因是**封号风险**：

| 机器 | 身份 | 用途 | 浏览器登录 |
|------|------|------|-----------|
| **Windows** | 数据采集机 | 对标账号采集、爆款分析、搜同赛道博主 | ❌ 不登录峰峰号 |
| **Mac** | 峰峰操作机 | 登录创作者中心、发布视频、看完播率等深度数据 | ✅ 登录峰峰号 |

**绝对不能合并到同一台机器。** 抖音会关联IP/设备指纹/cookie，对标采集的污染cookie会导致峰峰号被关联封号。

## Agent职责

### 1. 对标采集（Windows浏览器）
- 搜索赛道爆款，采集播放/标题/封面特征
- 输出：`shared/data.json`
- 不涉及任何账号操作

### 2. 创作者中心（Mac浏览器）
- 登录峰峰自己的抖音创作者中心
- 通过 `work_list` API批量拉取所有视频的**深度数据**（完播率/2s跳出/涨粉/流量来源）
- 输出：`shared/video-index.json`，以 `workId`（19位抖音视频ID）为唯一键

### 3. 情报站
- 读 `video-index.json`，输出全量诊断报告
- 读 `data.json` 对标数据作为赛道趋势参照（暂未深度整合）
- 输出：`shared/diagnosis/` 目录下的诊断报告

### 4. 脚本生成器
- 根据素材 + 最新数据，产出经过严格自检的脚本
- 日常口播（10-15秒，占80%）+ 精选视频（60-90秒，占20%）
- 输出：`shared/scripts/` 目录下标准化脚本

### 5. 标题封面官
- 读脚本产出标题 + 封面方案
- 支持抖音和小红书双平台输出
- 输出：标题方案 + 封面prompt列表

### 6. 素材管家
- 管理故事素材池 + 实拍素材库
- 方向分类、优先级标记、使用记录
- 输出：`shared/data.json`（素材池维护）

## 数据共享协议

### video-index.json（唯一事实源）
**所有子Agent的数据来源。** 以 `workId` 为唯一键，每条视频包含：

| 字段 | 说明 |
|------|------|
| workId | 19位抖音视频ID（唯一键） |
| canonicalTitle | 标题 |
| publishDateTime | ISO格式发布时间 |
| creatorSnapshot | 深度指标（完播率/2s跳出/涨粉/粉丝占比等20+指标） |
| checkpoints | 发后追踪时间点数据 |

位于 `D:\shared\video-index.json`（工作目录通过符号链接映射）

### data.json（对标 + 素材数据）
- 对标采集产出（Windows）
- 素材管家维护的素材池
- 使用痕迹记录

## 协作流程

```
1. 峰峰→总助："帮我看看最近数据怎么样"
2. 总助→Mac：启动创作者中心子Agent采最新深度数据
3. 创作者中心→video-index.json：写入增量更新
4. 总助→情报站：启动诊断子Agent
5. 情报站→诊断报告：产出分析报告
6. 总助→读报告：确认数据完整
7. 峰峰→总助：决定下一方向
8. 总助→素材管家：要素材
9. 总助→脚本生成器：写脚本
10. 脚本生成器→脚本：产出+自检
11. 总助：验收通过
12. 峰峰：实际发布（人工操作App）
13. 发布后→总助：记 publish-log.json
```

## 技术栈

- **AI模型：** DeepSeek-v4-flash（主模型）、Qwen2.5:7b（本地分析）
- **Agent框架：** OpenClaw（本地运行）
- **浏览器：** Chromium (target="host" for Windows, target="node" for Mac)
- **节点通信：** OpenClaw Node（MacBook Pro → sunlifeng-Mac）
- **数据存储：** JSON文件（本地，无数据库）
- **版本控制：** GitHub

## 核心原则

1. **总助不参与决策** — 只拉数据、调度子Agent、检查输出，不替峰峰定稿
2. **Token > 时间 > 完美** — 一切操作以省Token为优先
3. **workId唯一键** — 所有数据对齐基于workId，不靠标题匹配
4. **封号隔离** — 双机分工不可合并
5. **子Agent卡住→重试，不自己上手** — 三次不行报峰峰
6. **内容策略** — 80%口播日常 + 20%精选视频

## 快速启动

```bash
# 确认OpenClaw运行中
openclaw status

# 确认Mac节点已配对的
openclaw nodes status

# 启动日常心跳轮询 -> 自动触发数据采集
openclaw run heartbeat

# 或者手动触发
openclaw run "启动创作者中心采集"
```
